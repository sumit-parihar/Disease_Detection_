## 6. Method notes: how the two hash functions work (for the project log book)

### SHA-256 (exact copies)

- Input: the raw bytes of the image file. It does not look at the picture.
- The bytes are mixed through a fixed series of steps into a 256-bit fingerprint (64 hex characters).
- Same bytes give the same fingerprint. Changing a single byte gives a completely different one.
- Use here: certain detection of byte-identical files, within and across datasets. It cannot detect a resized or re-saved copy.
- Also used for the manifest sidecar (`manifest.csv.sha256`), which identifies the exact data version.

### pHash (look-alike copies), as computed by the `imagehash` library

1. Shrink the image to 32 x 32 pixels and convert to grey (1,024 pixel values).
2. Apply the DCT (discrete cosine transform). It turns the 1,024 pixel values into 1,024 pattern values. Each pattern value says how strongly one fixed wave pattern (for example "bright left, dark right", or fine stripes) is present in the image. The values sit in a 32 x 32 grid: coarse patterns top-left, finer patterns towards the bottom-right.
3. Keep only the top-left 8 x 8 corner, the 64 coarsest patterns. Chosen by position, not by size. Coarse patterns describe the overall light and dark layout and barely change with resizing, re-saving or small brightness changes. Fine patterns change easily, so they are ignored.
4. Take the median of these 64 values (the middle of the sorted list; half of the values lie above it and half below). The median comes from the 64 pattern values, not from the pixel values.
5. Each value above the median becomes bit 1, every other value bit 0. Result: a 64-bit hash, stored as 16 hex characters.

- Distance between two images = Hamming distance = number of bit positions where their hashes differ (0 to 64). Unrelated images typically differ by about 28 to 36 bits.

### Why only even distances occur

- Because of the median step, every hash has exactly 32 ones and 32 zeros. Checked on test images (every hash had 32 ones); not separately checked on the real manifest.
- If two hashes both have 32 ones, every position where one has a 1 and the other a 0 is balanced by a position the other way round. Differences come in pairs, so the distance is always 0, 2, 4, 6, 8, 10, ...
- Example: a = 32 ones then 32 zeros; b = same except bit 1 and bit 64 swapped: they differ in 2 places, distance 2.
- Consequence: a limit of 5 is the same as a limit of 4. The zero counts at distances 1, 3, 5, 7, 9 in `phash_sweep_table.csv` are not missing data; those distances cannot occur.

### Why SHA-256 and pHash are used together

- SHA-256 gives certainty for exact copies, so they are not reviewed by eye.
- pHash finds copies that were resized, re-saved or re-framed; each such candidate needs a manual check because look-alike leaves can also get close hashes (pairs 17 to 19, and 33 of the 42 distance-6 pairs).
- Share of real same-leaf pairs by distance in our review: 0: 2 of 2, 2: 7 of 7, 4: 7 of 10, 6: 9 of 42 (21%).

Keywords: apple leaf disease; failure prediction; selective classification; distribution shift; confidence estimation; MobileNetV3-Small; source-only learning; domain generalization\
1\. Introduction\
Image-based deep learning has become a widely studied approach for automated plant disease recognition. Early work using the PlantVillage dataset demonstrated that convolutional neural networks can achieve high accuracy on controlled leaf-image benchmarks while also emphasizing the need to evaluate generalization beyond curated image conditions [1]. For apple-specific field evaluation, the Plant Pathology Challenge 2020 dataset was subsequently created from real-world orchard imagery with variation in illumination, background, viewing angle, surface, focus, and noise [2]. Together, controlled and field datasets expose an important distinction between benchmark classification accuracy and practical deployment reliability.\
Recent literature shows that the deployment problem is not limited to classification accuracy. Under controlled-to-field distribution shift, a classifier can become substantially less accurate while retaining high confidence. Xiang, Shi, and Zhu evaluated this reliability gap in plant-disease classification and reported that standard calibration, selective prediction, out-of-distribution scoring, and ensemble strategies do not necessarily eliminate the problem [3]. Apple-specific studies have also begun to report calibration and cross-dataset evaluation, which means that neither apple cross-dataset classification nor calibration alone can be presented as a novel contribution [4,5,10].\
A second line of prior work establishes that explicit confidence or rejection mechanisms are not new in machine learning. DeVries and Taylor proposed a learned confidence branch [6], while SelectiveNet jointly learned prediction and selection functions in an end-to-end selective-classification framework [7]. Consequently, the contribution of the present study is not the generic idea of adding a confidence head. The narrower question is whether a computationally lightweight failure-prediction mechanism, learned entirely from source-domain apple data, can remain useful for identifying erroneous predictions in a strictly unseen field domain without using target-domain data for adaptation, calibration, threshold selection, or model selection.\
This study therefore proposes a strict source-only protocol in which a lightweight MobileNetV3-Small disease classifier is trained on controlled apple-leaf images, frozen, and augmented with a small failure-prediction head trained only from source-domain errors. The proposed reliability mechanism is compared with maximum softmax probability, predictive entropy, probability margin, temperature-scaled confidence, and a logits-only learned error predictor. The primary planned outcome is target-domain area under the risk-coverage curve (AURC), rather than classification accuracy alone.\
1.1 Problem Statement\
Deep-learning classifiers trained on controlled apple-leaf images may lose classification performance when applied to field images acquired under different environmental and imaging conditions. More importantly, confidence scores may remain high even when predictions become incorrect. A deployment-oriented system therefore needs not only disease discrimination but also a mechanism for identifying predictions that are likely to be unreliable under distribution shift. Existing work already covers apple cross-dataset recognition, plant-disease domain generalization, probability calibration, uncertainty estimation, and learned selective prediction. What remains provisionally unresolved within the literature examined for this study is whether a small failure-prediction mechanism trained solely from source-domain apple data can improve error discrimination and selective reliability on a strictly unseen field domain beyond established confidence baselines.\
1.2 Revised Research Gap\
Existing studies have established cross-dataset and unseen-domain apple disease recognition and have demonstrated that confidence calibration and selective prediction can degrade under controlled-to-field distribution shift. General machine-learning research has also developed learned confidence and selective-classification mechanisms. However, within the literature examined here, it remains uncertain whether a computationally lightweight failure-prediction mechanism trained solely from source-domain apple disease data can improve discrimination of correct versus incorrect predictions on a strictly unseen field domain beyond established post-hoc confidence and selective-classification baselines, without using target-domain data for adaptation, calibration, or threshold selection.\

1.3 Research Questions\
Primary RQ: Does a lightweight failure-prediction mechanism trained solely from source-domain apple images improve selective reliability on an unseen field-domain apple dataset compared with established confidence baselines?\
RQ2: How much does the frozen source-trained disease classifier's performance change when transferred from controlled source images to unseen field images?\
RQ3: Does the proposed failure predictor discriminate incorrect target-domain predictions better than classifier-output-only methods?\
RQ4: How well do confidence/rejection thresholds selected exclusively from source data transfer to the unseen target domain?\
RQ5: Do visual features and classifier logits each contribute useful information to failure prediction?\
RQ6: What computational overhead does the proposed reliability mechanism add to the lightweight disease classifier?\
1.4 Objectives\
•	Train a lightweight three-class apple disease classifier using source-domain data only.\
•	Quantify source-to-target classification degradation under a natural controlled-to-field distribution shift.\
•	Train a lightweight failure predictor from errors produced by the frozen classifier on a separate source-only reliability subset.\
•	Compare the proposed failure predictor with maximum softmax probability, predictive entropy, top-1/top-2 probability margin, temperature-scaled confidence, and a logits-only learned error predictor.\
•	Evaluate target-domain error discrimination, calibration, and risk-coverage behaviour.\
•	Test the transfer of source-selected 80% and 90% coverage thresholds to the unseen target domain.\
•	Perform features-only and logits-only ablations.\
•	Quantify parameter, model-size, and inference-time overhead.\
1.5 Hypothesis\
The primary directional hypothesis is that the proposed failure-prediction method will yield lower target-domain AURC than maximum softmax probability. The corresponding null hypothesis is that the proposed method will have equal or higher target-domain AURC. Comparisons with the remaining baselines will be treated as secondary analyses. Failure to outperform a baseline will be reported as a valid result rather than treated as an implementation failure.\
2\. Related Work\
2.1 Controlled and Field Apple Disease Datasets\
PlantVillage is a widely used controlled-condition plant-disease image resource. Mohanty, Hughes, and Salathe used 54,306 healthy and diseased leaf images from PlantVillage to demonstrate the feasibility of deep convolutional classification while noting the importance of generalization beyond controlled datasets [1]. For apple-specific field evaluation, Thapa et al. introduced the Plant Pathology Challenge 2020 dataset, containing real-world apple foliar disease images captured under variable illumination, angles, backgrounds, surfaces, focus, and noise [2]. These datasets motivate a controlled-source to field-target evaluation.\
2.2 Apple Cross-Dataset and Domain-Generalization Research\
Cross-dataset apple disease recognition has already been directly investigated. Yan and Wang developed a cross-dataset discriminant subspace learning method for apple leaf disease identification using multiple source datasets and a distinct target dataset [8]. Zhan et al. later established laboratory-to-field domain-generalization benchmarks for plant leaf disease recognition, including an apple benchmark, and proposed a domain-generalization method based on style-sensitive distillation and prototype matching [5]. These studies prevent the present work from claiming that apple cross-dataset recognition or laboratory-to-field generalization is itself novel.\
2.3 Reliability, Calibration, and Selective Prediction\
Calibration and selective prediction address different reliability questions. Calibration evaluates whether reported probabilities correspond to empirical correctness frequencies, whereas selective prediction evaluates whether a system can identify when to abstain. Guo et al. established temperature scaling as a strong post-hoc calibration baseline [9]. DeVries and Taylor proposed learning a confidence branch for neural-network predictions [6], and Geifman and El-Yaniv developed SelectiveNet to jointly learn classification and selection [7]. These works establish that a two-output or rejection-aware architecture is not, by itself, a novel methodological contribution.\
Within plant-disease research, reliability under shift is also an active topic. Xiang et al. evaluated calibration, selective prediction, out-of-distribution scoring, ensembles, and adaptation under controlled-to-field shift [3]. Wu et al. combined unsupervised domain adaptation with uncertainty regularization for plant-disease recognition in the wild [11]. Apple-specific recent work, including LeafSightX and the ContinuousLayer study, reports confidence/calibration analyses and external or cross-dataset evaluation [4,10]. Accordingly, the present study narrows its contribution to source-only lightweight failure prediction evaluated against strict unseen-domain errors.\

3\. Materials and Methods\
3.1 Study Design\
The study is designed as a quantitative computational experiment with strict source-only development and external cross-domain evaluation. All model training, hyperparameter selection, early stopping, calibration, reliability-head training, and threshold selection will use source-domain information only. The target field dataset will remain unavailable to the development pipeline until all model and threshold decisions are frozen. This design differs from domain adaptation because no target-domain image, label, statistic, or prediction outcome may influence model development.\
3.2 Planned Data Sources\
The planned source dataset is the original non-augmented color apple subset of PlantVillage, restricted to Healthy, Apple Scab, and Cedar Apple Rust. 3.7 Disease Classifier\
The planned backbone is MobileNetV3-Small with ImageNet pretraining, alpha = 1.0, 224 x 224 RGB input, and the original ImageNet classification head removed. Global average pooling yields a 576-dimensional representation. A dropout layer with rate 0.20 and a three-unit linear classification layer will produce logits for Healthy, Scab, and Cedar Apple Rust. The planned classifier has approximately 940,851 parameters based on the current design; the exact count must be confirmed from the implemented framework [RESULTS PENDING].\
3.8 Failure-Prediction Head\
The reliability mechanism will receive the frozen 576-dimensional image feature vector concatenated with the three frozen disease-classifier logits, forming a 579-dimensional input. This input is passed through Dense(64, ReLU), dropout 0.30, and Dense(1, sigmoid) to estimate the probability that the disease prediction is incorrect. L2 kernel regularization of 1e-4 is planned for the hidden layer. The head contains approximately 37,185 parameters, producing an estimated total system size below one million parameters; the exact runtime parameter count remains [RESULTS PENDING].\
Component	Planned configuration	Purpose\
Disease backbone	MobileNetV3-Small, ImageNet pretrained, include_top=False	Feature extraction\
Pooling	Global average pooling -> 576-D	Compact representation\
Disease head	Dropout(0.20) -> Dense(3, linear) -> Softmax	Three-class disease prediction\
Reliability input	576 features + 3 logits = 579-D	Representation + classifier evidence\
Failure head	Dense(64, ReLU, L2=1e-4) -> Dropout(0.30) -> Dense(1, sigmoid)	P(classifier error)\
\
3.9 Loss Functions\
Disease classification will use class-weighted categorical cross-entropy. Class weights will be calculated only from S-train using w_c = N/(C\*n_c), where N is the number of source training images, C = 3 classes, and n_c is the training count for class c. The failure predictor will use weighted binary cross-entropy with classifier error treated as the positive class. The positive weight will be computed from reliability-training errors and capped at 5 to avoid unstable gradients when errors are rare.\
3.10 Training Schedule\
Phase	Planned settings	Selection criterion\
Disease head warm-up	Backbone frozen; Adam; lr=1e-3; batch=32; max 12 epochs; early stopping patience=3	Source validation loss\
Backbone fine-tuning	Unfreeze final three MobileNetV3 inverted-residual blocks + final 1x1 conv; BatchNorm frozen; AdamW; lr=3e-5; weight decay=1e-5; max 20 epochs; patience=5	Source validation macro-F1\
Failure head	Disease classifier fully frozen; Adam; lr=5e-4; batch=64; max 30 epochs; patience=5	Reliability-validation AUPRC-error\
\
Source augmentation for disease training is limited to mild horizontal flipping, rotation up to +/-15 degrees, zoom up to +/-10%, and contrast up to +/-10%. These choices will be frozen before any target evaluation. Final disease-model training will use the development-determined epoch counts without target-dependent early stopping.\
3.11 Source-Only Failure Generation\
Because the source classifier may make relatively few clean-image errors, the S-reliability subset will be used to generate prespecified source-only hard views after it is separated into reliability-training and reliability-validation partitions by original image ID. The planned single perturbations are brightness factor 0.7-1.3, contrast factor 0.7-1.3, Gaussian blur sigma 0.5-1.5, and Gaussian noise sigma 0.01-0.05 in normalized pixel space. Each failure label equals 1 when the frozen disease classifier predicts the wrong class and 0 otherwise. At least 50 positive reliability-training errors are required; otherwise the protocol must be explicitly revised and documented rather than silently increasing perturbation severity.\

3.13 Calibration and Threshold Selection\
Temperature scaling will fit a single scalar temperature on S-calibration only by minimizing negative log-likelihood. Two deployment thresholds will be selected from S-calibration only: tau80 targeting approximately 80% source calibration coverage, and tau90 targeting approximately 90% coverage. These numerical thresholds will be frozen before target inference and applied unchanged to S-test and target data. Target-specific threshold recalibration is prohibited in the primary experiment.\
3.14 Target Evaluation and Label Unblinding\
All target images will first be processed by the frozen disease classifier and all frozen reliability methods without consulting target labels. Disease predictions, probability vectors, confidence/failure scores, and model identifiers will be saved to an immutable prediction file and hashed. Only then will target labels be joined. Primary closed-set analysis will use Healthy, Scab, and Rust images. Multiple-disease images may be analyzed separately only as explicitly exploratory observations and will not influence the primary model-selection or threshold decisions.\

The primary endpoint is target-domain AURC. Lower AURC indicates a better risk-coverage trade-off. The principal comparison is Delta AURC = AURC_proposed - AURC_MSP. Support for the directional hypothesis requires a negative Delta AURC and a paired 95% bootstrap confidence interval lying below zero. If the interval includes zero, the evidence will be treated as inconclusive; if it lies above zero, the proposed method will be interpreted as performing worse than MSP.\
3.16 Statistical Analysis and Sample-Size Rationale\
The study will use all eligible images from the prespecified public datasets rather than selecting an arbitrary sample size. A defensible effect size for target-domain AURC improvement is not yet available, so an invented power calculation would be inappropriate. Precision will instead be quantified through approximately 2,000 paired stratified bootstrap resamples of the target evaluation set. Three prespecified training seeds are planned, and all seed-specific results will be reported. Exact class-specific error counts will be shown because rare errors can make classwise AUPRC and calibration estimates unstable.\

3.18 Bias, Uncertainty, and Threats to Validity\
•	Data leakage: target information must not influence development; prediction files are frozen before target labels are joined.\
•	Duplicate leakage: exact and perceptual duplicate checks are required within source splits and across source/target datasets.\
•	Construct validity: calibration, uncertainty, OOD detection, and failure prediction are related but distinct concepts and will not be treated as interchangeable.\
•	Synthetic-error mismatch: source perturbations may not resemble natural field failures; this will be treated as a limitation rather than hidden.\
•	Class-prior shift: source and target class distributions differ, so macro and classwise analyses are required.\
•	Single source-target pair: conclusions cannot automatically generalize to all orchards, cameras, regions, cultivars, seasons, or disease severities.\
•	Researcher degrees of freedom: augmentation, corruption ranges, metrics, baselines, and thresholds are prespecified before target evaluation.\
•	Statistical uncertainty: bootstrap confidence intervals and seed-level reporting will be used rather than relying on single point estimates.\

Dataset.py:
"""
dataset.py  -  Step 4: loads the images and turns them into numbers the neural
network can read (tensors). Used by every training and evaluation script.

WHAT THIS FILE DOES
-------------------
1. Reads which image belongs to which subset from splits/split_assignments.csv
   (made by make_splits.py) and gives you the images of ONE subset at a time.
2. Applies the image preparation ("transform") described in the paper.
3. Gives the images to the model in small groups called batches.

THE TWO TRANSFORMS
------------------
Both transforms first do the same preparation:
    open image -> make it RGB -> resize to 224 x 224
    -> scale pixel values from 0..255 to 0..1
    -> subtract the ImageNet mean and divide by the ImageNet std, per colour.
The last step is needed because the MobileNetV3-Small we start from was
pretrained on ImageNet with exactly this scaling.

  eval transform  : only the preparation above. Used for s_val, s_reliability,
                    s_calibration, s_test and for the target (PP2020).
  train transform : the preparation plus the mild augmentation of the paper
                    (Section 3.8): horizontal flip, rotation up to +/-15
                    degrees, zoom +/-10%, contrast +/-10%. ONLY for s_train.
                    The paper says augmentation is never applied to
                    validation, calibration or test sets, so the code refuses
                    to use it on any other subset.

CHOICES THE PAPER DOES NOT SPECIFY (made here, before any target result)
------------------------------------------------------------------------
  * Resizing: the whole image is resized straight to 224 x 224, for BOTH
    datasets, with the same rule. Source images are square (256 x 256); the
    target images are not, so they get squeezed a little. The other options
    (cutting out the centre, adding borders) would remove parts of the leaf
    or add fake borders. Whatever is chosen, it must be the same for source and
    target and must not be changed after seeing target results.
  * Flip probability 0.5 (standard for "horizontal flips").
  * Rotated-in corners are filled with black.
  * No automatic correction of photo orientation (EXIF) is applied, for either
    dataset.
  * Normalisation uses the ImageNet mean/std (PyTorch convention for
    pretrained MobileNetV3).

BATCH SIZES
-----------
The paper draft v2 gives 32 (disease training) and 64 (failure head). They are
set in config.py (BATCH_SIZE, EVAL_BATCH_SIZE).

THE TARGET DATASET AND THE SEAL
-------------------------------
TargetDataset gives only the image and its path. It never gives labels. The
paper says target labels may be used only after predictions are frozen and
saved, so labels will be read by the final evaluation script, not here.

HOW TO CHECK IT (project root, venv active):
    python src/dataset.py          quick check (a few images per subset) and a
                                   GPU memory test with batch size 32
    python src/dataset.py --full   opens every image of every subset

GPU TEST
--------
If a GPU is found, the check also sends one augmented batch (config.BATCH_SIZE
= 32) through an UNTRAINED MobileNetV3-Small, forwards and backwards, and
prints the peak GPU memory. This is only a memory test: nothing is trained or
saved, and no pretrained weights are downloaded.

MANIFEST_FILE = MANIFEST_DIR / "manifest.csv"
SUBSETS = list(SPLIT_PROPORTIONS.keys())
TRAIN_SUBSET = "s_train"          # the only subset that may be augmented

IMAGENET_MEAN = (0.485, 0.456, 0.406)
IMAGENET_STD = (0.229, 0.224, 0.225)

# Augmentation limits from the paper (Section 3.8)
FLIP_PROBABILITY = 0.5            # not given in the paper (standard value)
ROTATION_DEGREES = 15
ZOOM_RANGE = (0.9, 1.1)           # zoom up to +/-10%
CONTRAST_RANGE = 0.1              # contrast factor 0.9 to 1.1


# ---------------------------------------------------------------------------
# PART 1: transforms
# ---------------------------------------------------------------------------
def _preparation():
    """Steps shared by every transform (after any augmentation)."""
    return [
        T.ToTensor(),                                  # 0..255 -> 0..1, shape 3 x H x W
        T.Normalize(IMAGENET_MEAN, IMAGENET_STD),
    ]


def build_eval_transform():
    """Resize to 224 x 224, scale, normalise. No randomness."""
    return T.Compose([T.Resize((IMAGE_SIZE, IMAGE_SIZE))] + _preparation())


def build_train_transform():
    """Same as the eval transform, plus the mild random augmentation."""
    return T.Compose([
        T.Resize((IMAGE_SIZE, IMAGE_SIZE)),
        T.RandomHorizontalFlip(p=FLIP_PROBABILITY),
        T.RandomAffine(degrees=ROTATION_DEGREES, scale=ZOOM_RANGE, fill=0),
        T.ColorJitter(contrast=CONTRAST_RANGE),
    ] + _preparation())


def load_image(relative_path):
    """Open an image from its path in the manifest (relative to the project
    root) and make sure it has 3 colour channels."""
    return Image.open(PROJECT_ROOT / relative_path).convert("RGB")


# ---------------------------------------------------------------------------
# PART 2: datasets
# ---------------------------------------------------------------------------
class SourceDataset(Dataset):
    """The PlantVillage images of ONE subset.
    Each item is (image tensor, class index 0/1/2, image path)."""

    def __init__(self, subset, augment=False):
        if subset not in SUBSETS:
            raise ValueError(f"Unknown subset '{subset}'. Choose from {SUBSETS}.")
        if augment and subset != TRAIN_SUBSET:
            raise ValueError("Augmentation is only allowed on s_train "
                             "(paper: not on validation, calibration or test sets).")
        if not SPLIT_FILE.exists():
            sys.exit(f"{SPLIT_FILE} not found. Run make_splits.py first.")

        table = pd.read_csv(SPLIT_FILE)
        table = table[table["subset"] == subset].sort_values("path").reset_index(drop=True)
        self.subset = subset
        self.paths = table["path"].tolist()
        self.label_names = table["label"].tolist()
        self.labels = [CLASS_TO_INDEX[name] for name in self.label_names]
        self.transform = build_train_transform() if augment else build_eval_transform()

    def __len__(self):
        return len(self.paths)

    def __getitem__(self, index):
        image = self.transform(load_image(self.paths[index]))
        return image, self.labels[index], self.paths[index]


class TargetDataset(Dataset):
    """All labelled PP2020 train images (1,821) for the frozen pipeline.
    Each item is (image tensor, image path). NO labels are returned: the paper
    keeps target labels sealed until predictions are frozen and saved."""

    def __init__(self):
        if not MANIFEST_FILE.exists():
            sys.exit(f"{MANIFEST_FILE} not found. Run audit_dataset.py first.")
        manifest = pd.read_csv(MANIFEST_FILE, keep_default_na=False)
        manifest["decode_ok"] = manifest["decode_ok"].astype(str) == "True"
        target = manifest[(manifest["dataset"] == "target") & manifest["decode_ok"]]
        self.paths = sorted(target["path"].tolist())
        self.transform = build_eval_transform()

    def __len__(self):
        return len(self.paths)

    def __getitem__(self, index):
        return self.transform(load_image(self.paths[index])), self.paths[index]

# PART 3: loaders (batches)

def make_loader(dataset, batch_size, shuffle=False, num_workers=0, seed=SEED):
    """Wrap a dataset so the model receives batches.
    batch_size has no default on purpose: the paper draft gives 32 (disease
    training) and 64 (failure head); the values live in config.py.
    shuffle=True mixes the order each epoch (use it only for training); the
    mixing is seeded so a run can be repeated.
    num_workers=0 loads images in the main process (safest on Windows)."""
    generator = torch.Generator()
    generator.manual_seed(seed)
    return DataLoader(
        dataset,
        batch_size=batch_size,
        shuffle=shuffle,
        num_workers=num_workers,
        generator=generator if shuffle else None,
        pin_memory=torch.cuda.is_available(),
    )


def get_source_loader(subset, batch_size, train=False, num_workers=0):
    """Loader for one source subset. train=True means: augmentation + shuffling
    (allowed for s_train only)."""
    dataset = SourceDataset(subset, augment=train)
    return make_loader(dataset, batch_size, shuffle=train, num_workers=num_workers)

def check_tensor(image):
    ok = tuple(image.shape) == (3, IMAGE_SIZE, IMAGE_SIZE) and image.dtype == torch.float32
    return ok and bool(torch.isfinite(image).all())


def gpu_check(batch_size):
    """Send one augmented batch through an untrained MobileNetV3-Small on the GPU
    (forward + backward) to confirm the batch size fits in GPU memory."""
    print("\nGPU test:")
    if not torch.cuda.is_available():
        print("  No GPU found. PyTorch will use the CPU (slow).")
        print("  Usually this means the CPU-only PyTorch was installed. Install the")
        print("  CUDA build from pytorch.org for your NVIDIA GPU.")
        return True
    from torchvision.models import mobilenet_v3_small

    device = torch.device("cuda")
    total_gb = torch.cuda.get_device_properties(0).total_memory / 1024 ** 3
    print(f"  GPU: {torch.cuda.get_device_name(0)} ({total_gb:.1f} GB)")
    try:
        model = mobilenet_v3_small(weights=None).to(device)   # untrained, no download
        model.train()
        loader = make_loader(SourceDataset(TRAIN_SUBSET, augment=True), batch_size, shuffle=True)
        images, _, _ = next(iter(loader))
        images = images.to(device)
        torch.cuda.reset_peak_memory_stats()
        model(images).float().mean().backward()               # throwaway pass
        torch.cuda.synchronize()
        peak_gb = torch.cuda.max_memory_allocated() / 1024 ** 3
        print(f"  Batch of {len(images)}: forward + backward OK, "
              f"peak GPU memory {peak_gb:.2f} GB of {total_gb:.1f} GB")
        return True
    except torch.cuda.OutOfMemoryError:
        print(f"  CUDA out of memory with batch size {batch_size}. "
              "Set BATCH_SIZE = 16 in config.py and run again.")
        return False


def self_check(full):
    print("Checking the data loader...\n")
    table = pd.read_csv(SPLIT_FILE) if SPLIT_FILE.exists() else sys.exit(
        f"{SPLIT_FILE} not found. Run make_splits.py first.")
    all_ok = True

    print(f"{'subset':<15}{'images':>8}{'in file':>9}   classes (healthy / scab / rust)")
    for subset in SUBSETS:
        dataset = SourceDataset(subset)
        in_file = int((table["subset"] == subset).sum())
        counts = [dataset.labels.count(CLASS_TO_INDEX[name]) for name in CLASS_NAMES]
        status = "OK" if len(dataset) == in_file else "MISMATCH"
        all_ok &= status == "OK"
        print(f"{subset:<15}{len(dataset):>8}{in_file:>9}   {counts}  {status}")

        indices = range(len(dataset)) if full else range(min(4, len(dataset)))
        for index in indices:
            image, label, path = dataset[index]
            if not check_tensor(image):
                print(f"   PROBLEM with {path}: shape {tuple(image.shape)}")
                all_ok = False

    # the training transform (augmentation) on a few s_train images
    train_set = SourceDataset(TRAIN_SUBSET, augment=True)
    batch_images, batch_labels, _ = next(iter(make_loader(train_set, batch_size=4, shuffle=True)))
    train_ok = tuple(batch_images.shape) == (4, 3, IMAGE_SIZE, IMAGE_SIZE)
    all_ok &= train_ok
    print(f"\nTraining batch (augmented, shuffled): shape {tuple(batch_images.shape)}, "
          f"labels {batch_labels.tolist()}  {'OK' if train_ok else 'PROBLEM'}")

    # augmentation must be refused on other subsets
    try:
        SourceDataset("s_test", augment=True)
        print("PROBLEM: augmentation was allowed on s_test")
        all_ok = False
    except ValueError:
        print("Augmentation on s_test is refused  OK")

    # the target dataset: only images, no labels
    target = TargetDataset()
    item = target[0]
    target_ok = len(item) == 2 and check_tensor(item[0])
    if full:
        for index in range(len(target)):
            target_ok &= check_tensor(target[index][0])
    all_ok &= target_ok
    print(f"Target dataset: {len(target)} images, each item = (image, path), no labels  "
          f"{'OK' if target_ok else 'PROBLEM'}")

    all_ok &= gpu_check(BATCH_SIZE)

    print("\n" + ("ALL CHECKS PASSED" if all_ok else "SOME CHECKS FAILED, send this output for help"))
    return all_ok


if __name__ == "__main__":

"""\
model.py  -  Step 5a: the main model (the disease classifier).\
\
WHAT THIS FILE DOES\
\-------------------\
It defines the model that looks at a leaf photo and answers: healthy, scab or\
rust (paper draft v2, Section 3.7). It only DEFINES the model. Training is in\
train_classifier.py.\
\
THE MODEL\
\---------\
&#x20; photo (3 x 224 x 224)\
&#x20;   -> MobileNetV3-Small, already trained on ImageNet photos\
&#x20;      (the part that "reads" the picture; it ends with 576 numbers per image)\
&#x20;   -> average over the picture  -> 576 numbers\
&#x20;   -> dropout 0.20              (randomly hides 20% of the numbers while\
&#x20;                                 training, so the model does not memorise)\
&#x20;   -> one linear layer with 3 outputs ("logits": one score each for\
&#x20;      healthy, scab, rust)\
The class with the highest score is the prediction.\
\
TWO TRAINING MODES (paper Section 3.10)\
\---------------------------------------\
&#x20; Phase A: only the 3-output layer can change; the MobileNet part is locked.\
&#x20; Phase B: the 3-output layer plus the LAST part of MobileNet can change\
&#x20;          (the final three inverted-residual blocks and the final 1x1\
&#x20;          convolution, modules 9, 10, 11 and 12 of the network).\
In both phases the "BatchNorm" layers stay frozen: they keep the statistics\
they learned on ImageNet and never update them.\
\
extract_features() returns the 576 numbers per image. The failure head (a later\
step) will use them together with the 3 scores.\
\
PARAMETER COUNT (paper Appendix B)\
\----------------------------------\
The paper planned 939,120 (MobileNet part) + 1,731 (output layer) = 940,851,\
and says the exact number must be confirmed from the real implementation.\
The PyTorch (torchvision) MobileNetV3-Small has a slightly different number\
for its MobileNet part. Running this file prints both, so the difference can be\
reported honestly in the paper.\
\
HOW TO CHECK IT (project root, venv active):\
&#x20;   python src/model.py\
(builds the model without downloading weights, prints the parameter counts and\
runs the checks)\
"""\
\
import torch\
from torch import nn\
from torchvision.models import MobileNet_V3_Small_Weights, mobilenet_v3_small\
\
from config import DISEASE_DROPOUT, FEATURE_DIM, IMAGE_SIZE, NUM_CLASSES\
\
\# Modules of torchvision's MobileNetV3-Small "features" list that are trained in\
\# phase B: three inverted-residual blocks (9, 10, 11) and the final 1x1 conv (12).\
PHASE_B_MODULES = (9, 10, 11, 12)\
\
\# Numbers planned in the paper (Appendix B)\
PAPER_BACKBONE_PARAMS = 939_120\
PAPER_HEAD_PARAMS = 1_731\
PAPER_CLASSIFIER_PARAMS = 940_851\
\
\
class DiseaseClassifier(nn.Module):\
&#x20;   def \_\_init\_\_(self, pretrained=True):\
&#x20;       """pretrained=True downloads the ImageNet weights the first time (about\
&#x20;       10 MB) and needs internet. pretrained=False gives a random model, only\
&#x20;       for quick tests."""\
&#x20;       super().\_\_init\_\_()\
&#x20;       weights = MobileNet_V3_Small_Weights.IMAGENET1K_V1 if pretrained else None\
&#x20;       self.features = mobilenet_v3_small(weights=weights).features   # the MobileNet part\
&#x20;       self.pool = nn.AdaptiveAvgPool2d(1)                            # average over the picture\
&#x20;       self.dropout = nn.Dropout(DISEASE_DROPOUT)\
&#x20;       self.fc = nn.Linear(FEATURE_DIM, NUM_CLASSES)                  # 576 -> 3 scores\
\
&#x20;   \# --- forward passes -----------------------------------------------------\
&#x20;   def extract_features(self, images):\
&#x20;       """576 numbers per image (before dropout and the output layer)."""\
&#x20;       return torch.flatten(self.pool(self.features(images)), 1)\
\
&#x20;   def forward(self, images):\
&#x20;       """3 scores (logits) per image: healthy, scab, rust."""\
&#x20;       return self.fc(self.dropout(self.extract_features(images)))\
\
&#x20;   \# --- freezing -----------------------------------------------------------\
&#x20;   def set_phase_a(self):\
&#x20;       """Lock the whole MobileNet part. Only the output layer can learn."""\
&#x20;       for parameter in self.features.parameters():\
&#x20;           parameter.requires_grad = False\
&#x20;       for parameter in self.fc.parameters():\
&#x20;           parameter.requires_grad = True\
\
&#x20;   def set_phase_b(self):\
&#x20;       """Also let the last part of MobileNet learn (BatchNorm stays frozen)."""\
&#x20;       self.set_phase_a()\
&#x20;       for index in PHASE_B_MODULES:\
&#x20;           for parameter in self.features[index].parameters():\
&#x20;               parameter.requires_grad = True\
&#x20;       for module in self.features.modules():\
&#x20;           if isinstance(module, nn.BatchNorm2d):\
&#x20;               for parameter in module.parameters():\
&#x20;                   parameter.requires_grad = False\
\
&#x20;   def train(self, mode=True):\
&#x20;       """Normal train()/eval() switch, except that the BatchNorm layers of the\
&#x20;       MobileNet part ALWAYS stay in evaluation mode (frozen statistics)."""\
&#x20;       super().train(mode)\
&#x20;       for module in self.features.modules():\
&#x20;           if isinstance(module, nn.BatchNorm2d):\
&#x20;               module.eval()\
&#x20;       return self\
\
\
def count_parameters(model):\
&#x20;   """Return (all parameters, parameters that can currently learn)."""\
&#x20;   total = sum(p.numel() for p in model.parameters())\
&#x20;   trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)\
&#x20;   return total, trainable\

train_classifier.py

"""\
train_classifier.py  -  Step 5b: trains the main model (disease classifier) in\
the two rounds of the paper draft v2, Section 3.10.\
\
WHAT THIS FILE DOES\
\-------------------\
It teaches the model to say healthy / scab / rust, using ONLY the source images:\
&#x20; \* s_train : the images the model learns from\
&#x20; \* s_val   : images used to check progress, to pick the best version and to\
&#x20;             decide when to stop\
It never opens s_reliability, s_calibration, s_test or any PP2020 image.\
\
ROUND 1  "Phase A" (head warm-up)\
&#x20;   Only the 3-output layer learns (the MobileNet part is locked).\
&#x20;   Adam, learning rate 1e-3, at most 12 passes (epochs) over s_train.\
&#x20;   The best version = the one with the lowest validation loss.\
&#x20;   Training stops early if the validation loss has not improved for 3 epochs.\
ROUND 2  "Phase B" (fine-tuning)\
&#x20;   The last part of MobileNet and the 3-output layer learn, gently.\
&#x20;   AdamW, learning rate 3e-5, weight decay 1e-5, at most 20 epochs.\
&#x20;   The best version = the one with the highest validation macro-F1\
&#x20;   (the average of the F1 scores of the three classes, so rust counts as much\
&#x20;   as healthy). Early stop after 5 epochs without improvement.\
&#x20;   Phase B starts from the best model of phase A.\
\
LOSS\
\----\
Class-weighted cross-entropy. Rust has far fewer images than healthy, so a\
mistake on a rust image counts more. Weight of class c = N / (3 x n_c), where N\
is the number of s_train images and n_c the number of s_train images of class c.\
The weights are computed from s_train only.\
\
WHAT IT SAVES\
\-------------\
&#x20; models/disease_seed\<S>\_phaseA.pt          best model after round 1\
&#x20; models/disease_seed\<S>\_phaseB.pt          best model after round 2 (the final classifier)\
&#x20; results/disease_seed\<S>\_training_log.csv  one row per epoch\
&#x20; results/disease_seed\<S>\_run_record.json   seed, settings, library versions,\
&#x20;                                           data hashes, parameter counts, results\
(models/ is ignored by Git; results/ is kept.)\
Existing files are never overwritten unless you add --overwrite.\
\
HOW TO RUN (project root, venv active, GPU PyTorch installed):\
&#x20;   python src/train_classifier.py                  both rounds, seed 42\
&#x20;   python src/train_classifier.py --seed 43        another seed\
&#x20;   python src/train_classifier.py --phase A        round 1 only\
&#x20;   python src/train_classifier.py --phase B        round 2 only (needs the phase A file)\
The first run downloads the ImageNet weights (about 10 MB), so it needs internet.\
"""\

def train_one_epoch(model, loader, optimizer, weights, device):\
&#x20;   """One pass over s_train. Returns the weighted average training loss."""\
&#x20;   model.train()\
&#x20;   loss_sum, weight_sum = 0.0, 0.0\
&#x20;   for images, labels, \_ in tqdm(loader, leave=False, unit="batch"):\
&#x20;       images, labels = images.to(device), labels.to(device)\
&#x20;       optimizer.zero_grad(set_to_none=True)\
&#x20;       logits = model(images)\
&#x20;       batch_loss = nn.functional.cross_entropy(logits, labels, weight=weights, reduction="sum")\
&#x20;       batch_weight = weights[labels].sum()\
&#x20;       (batch_loss / batch_weight).backward()\
&#x20;       optimizer.step()\
&#x20;       loss_sum += batch_loss.item()\
&#x20;       weight_sum += batch_weight.item()\
&#x20;   return loss_sum / weight_sum\

&#x20;   loss_sum, weight_sum = 0.0, 0.0\

&#x20;   for images, labels, \_ in loader:\
&#x20;       images, labels = images.to(device), labels.to(device)\
&#x20;       logits = model(images)\
&#x20;       loss_sum += nn.functional.cross_entropy(logits, labels, weight=weights, reduction="sum").item()\

make_splits.py
"""
make_splits.py  -  Step 3: divides the PlantVillage (source) images into the
five subsets of the paper, keeping duplicate images together.

WHAT THIS FILE DOES (paper, Section 3.4)
----------------------------------------
Input : the 2,550 source images listed in manifests/manifest.csv.
Output: every image gets exactly one subset:
    s_train        50%   fit the disease classifier
    s_val          10%   model selection and early stopping
    s_reliability  15%   train and validate the failure-prediction head
    s_calibration  10%   temperature scaling and source-only thresholds
    s_test         15%   untouched in-domain reference

The split is
  * seeded       : the same seed (config.SEED) always gives the same result.
  * stratified   : each subset has about the same class mix
                   (healthy / scab / rust) as the whole source set.
  * group-aware  : images that are duplicates of each other form a GROUP, and
                   a whole group always goes into ONE subset. A group is never
                   cut between, for example, s_train and s_test.

WHERE THE GROUPS COME FROM (these 3 inputs, nothing else)
---------------------------------------------------------
  1. Exact copies    : source images with the same SHA-256 in manifest.csv
                       (the same information as duplicates_exact.csv).
  2. near_duplicate_review.csv : pairs YOU marked "duplicate" or "unsure".
  3. sweep_review.csv          : pairs YOU marked "duplicate" or "unsure".
Groups can chain: if A~B and B~C, then A, B and C are one group.
A pair with a different label is not special: it is grouped like any other pair
and the script reports it.

SOURCE IMAGES THAT MATCH A TARGET IMAGE
---------------------------------------
If a source image is a duplicate of a PP2020 image (exact copy, or a pair you
marked duplicate/unsure), the SOURCE image is left out of the split and written
to splits/source_exclusions.csv (paper rule: target stays untouched). The
image file itself is never deleted. In your data this list should be empty.

HOW THE IMAGES ARE ASSIGNED
---------------------------
For each class: (1) work out how many images each subset should get
(proportion x class size, rounded so the numbers add up); (2) sort the groups,
biggest first, with a seeded shuffle among equal sizes; (3) put each group into
the subset that is currently furthest below its target. Since almost all groups
are single images, the final counts end up almost exactly on target.

BEFORE IT RUNS
--------------
Every row of near_duplicate_review.csv and sweep_review.csv must have a decision
(duplicate / different / unsure). The script stops and tells you if not.

OUTPUT FILES (in splits/)
-------------------------
  split_assignments.csv         path, label, group_id, subset  (the result)
  split_assignments.csv.sha256  hash of that file
  groups_multi.csv              every group with more than one image, and why
  source_exclusions.csv         source images left out (normally empty)
  split_summary.txt             counts per subset and class, and the checks

Like the manifest, the split is meant to stay fixed. The script refuses to
overwrite it unless you add --overwrite.

HOW TO RUN (project root, venv active):
    python src/make_splits.py
"""

def load_review(path, name):

    review = pd.read_csv(path, keep_default_na=False)

class UnionFind:
    """Tiny helper that merges images into groups (A~B and B~C -> one group)."""

    def __init__(self, items):
        self.parent = {item: item for item in items}

    def find(self, item):
        while self.parent[item] != item:
            self.parent[item] = self.parent[self.parent[item]]
            item = self.parent[item]
        return item

    def union(self, a, b):
        root_a, root_b = self.find(a), self.find(b)
        if root_a != root_b:
            # keep the alphabetically smaller path as root so results are stable
            if root_a < root_b:
                self.parent[root_b] = root_a
            else:
                self.parent[root_a] = root_b


def collect_links(manifest, reviews):
    """Return (links, exclusions).
    links      : list of (path_a, path_b, reason), both images are SOURCE images
    exclusions : dict source_path -> reason (source image matches a target image)"""
    dataset_of = dict(zip(manifest["path"], manifest["dataset"]))
    links, exclusions = [], {}

    # 1. exact copies: images that share a SHA-256
    usable = manifest[manifest["decode_ok"]]
    for sha, group in usable.groupby("sha256"):
        if len(group) < 2:
            continue
        source_paths = sorted(group[group["dataset"] == "source"]["path"])
        target_paths = sorted(group[group["dataset"] == "target"]["path"])
        if target_paths:
            for path in source_paths:
                exclusions[path] = f"exact copy of target image {target_paths[0]}"
        else:
            for other in source_paths[1:]:
                links.append((source_paths[0], other, "exact SHA-256 copy"))

    # 2 and 3. pairs you marked duplicate / unsure
    for review_name, review in reviews:
        for _, row in review.iterrows():
            if row["decision"] not in DUPLICATE_DECISIONS:
                continue
            a, b = row["path_a"], row["path_b"]
            kinds = {dataset_of[a], dataset_of[b]}
            reason = f"{review_name} pair {row['pair_id']} ({row['decision']})"
            if kinds == {"source"}:
                links.append((a, b, reason))
            elif kinds == {"source", "target"}:
                source_path, target_path = (a, b) if dataset_of[a] == "source" else (b, a)
                exclusions[source_path] = f"{reason}, matches target image {target_path}"
            # both target: not part of the source split, ignored here
    return links, exclusions


def build_groups(pool, links):
    """pool: DataFrame of source images that stay in the split.
    Returns dict group_id -> list of paths, and dict path -> group_id."""
    finder = UnionFind(pool["path"].tolist())
    in_pool = set(pool["path"])
    used_links = [(a, b, why) for a, b, why in links if a in in_pool and b in in_pool]
    for a, b, _ in used_links:
        finder.union(a, b)

    members = defaultdict(list)
    for path in sorted(pool["path"]):
        members[finder.find(path)].append(path)
    ordered = sorted(members.values(), key=lambda paths: paths[0])
    groups, group_of = {}, {}
    for number, paths in enumerate(ordered, start=1):
        group_id = f"g{number:04d}"
        groups[group_id] = paths
        for path in paths:
            group_of[path] = group_id
    return groups, group_of, used_links

def target_counts(size):
    """How many of `size` images each subset should get (largest remainder)."""
    raw = {name: size * SPLIT_PROPORTIONS[name] for name in SUBSETS}
    counts = {name: int(value) for name, value in raw.items()}
    leftover = size - sum(counts.values())
    by_fraction = sorted(SUBSETS, key=lambda name: (-(raw[name] - counts[name]), SUBSETS.index(name)))
    for name in by_fraction[:leftover]:
        counts[name] += 1
    return counts


def assign_groups(groups, group_label, rng):
    """Put every group into one subset, class by class."""
    subset_of_group = {}
    wanted = {}
    for label in CLASS_NAMES:
        label_groups = sorted(g for g in groups if group_label[g] == label)
        total = sum(len(groups[g]) for g in label_groups)
        wanted[label] = target_counts(total)
        rng.shuffle(label_groups)                                   # seeded shuffle
        label_groups.sort(key=lambda g: -len(groups[g]))            # biggest first (stable)
        current = {name: 0 for name in SUBSETS}
        for group_id in label_groups:
            deficit = {name: wanted[label][name] - current[name] for name in SUBSETS}
            best = max(deficit.values())
            choices = [name for name in SUBSETS if deficit[name] == best]
            chosen = choices[0] if len(choices) == 1 else rng.choice(choices)
            subset_of_group[group_id] = chosen
            current[chosen] += len(groups[group_id])
    return subset_of_group, wanted

def sha256_of_file(path):
    digest = hashlib.sha256()
    with open(path, "rb") as handle:
        for block in iter(lambda: handle.read(1024 * 1024), b""):
            digest.update(block)
    return digest.hexdigest()


def run_checks(assignments, groups, used_links, pool_size):
    results = []
    results.append(("every source image in the pool has exactly one subset",
                    len(assignments) == pool_size and assignments["path"].is_unique
                    and assignments["subset"].isin(SUBSETS).all()))
    spans = assignments.groupby("group_id")["subset"].nunique()
    results.append(("no group is split across subsets", bool((spans == 1).all())))
    subset_of = dict(zip(assignments["path"], assignments["subset"]))
    broken = [(a, b) for a, b, _ in used_links if subset_of[a] != subset_of[b]]
    results.append(("every duplicate pair (exact + reviewed) is in one subset", not broken))
    return results


def build_summary(assignments, wanted, groups, group_label, used_links, exclusions,
                  checks, manifest_hash, problems):
    lines = ["SPLIT SUMMARY", "=" * 60, ""]
    lines.append(f"Seed                    : {SEED}")
    lines.append(f"Manifest SHA-256 used   : {manifest_hash}")
    lines.append(f"Source images split     : {len(assignments)}")
    lines.append(f"Source images excluded  : {len(exclusions)} (see source_exclusions.csv)")
    multi = {g: p for g, p in groups.items() if len(p) > 1}
    lines.append(f"Groups                  : {len(groups)} "
                 f"({len(multi)} with more than one image, "
                 f"{sum(len(p) for p in multi.values())} images in them)")
    lines.append(f"Links used for grouping : {len(used_links)}")
    by_reason = Counter(why.split(" pair ")[0] for _, _, why in used_links)
    for reason, n in sorted(by_reason.items()):
        lines.append(f"    {reason:<28} {n}")

    lines += ["", "Images per subset and class (actual / target):"]
    header = f"  {'subset':<15}" + "".join(f"{label:>16}" for label in CLASS_NAMES) + f"{'total':>10}"
    lines.append(header)
    for name in SUBSETS:
        row = f"  {name:<15}"
        total = 0
        for label in CLASS_NAMES:
            actual = int(((assignments["subset"] == name) & (assignments["label"] == label)).sum())
            total += actual
            row += f"{f'{actual} / {wanted[label][name]}':>16}"
        row += f"{total:>10}"
        lines.append(row)
    lines.append("")
    share = assignments["subset"].value_counts(normalize=True)
    for name in SUBSETS:
        lines.append(f"  {name:<15} {100 * share.get(name, 0):5.1f}%  (paper: {100 * SPLIT_PROPORTIONS[name]:.0f}%)")

    lines += ["", "Checks:"]
    for text, ok in checks:
        lines.append(f"  {'PASS' if ok else 'FAIL'}  {text}")
    lines += ["", "Notes:"]
    lines += [f"  {p}" for p in problems] if problems else ["  none"]
    return "\n".join(lines) + "\n"

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--overwrite", action="store_true",
                        help="replace an existing split (use only on purpose)")
    args = parser.parse_args()

    make_folders()
    if ASSIGN_FILE.exists() and not args.overwrite:
        sys.exit(f"{ASSIGN_FILE} already exists. The split is meant to stay fixed. "
                 "Use --overwrite only if you really want to redo it.")

    manifest = load_manifest()
    reviews = [("near_duplicate_review", load_review(NEAR_REVIEW_FILE, "near_duplicate_review.csv")),
               ("sweep_review", load_review(SWEEP_REVIEW_FILE, "sweep_review.csv"))]
    problems = []

    source = manifest[manifest["dataset"] == "source"]
    undecodable = source[~source["decode_ok"]]
    for path in undecodable["path"]:
        problems.append(f"left out, could not be decoded: {path}")

    links, exclusions = collect_links(manifest, reviews)
    for path in undecodable["path"]:
        exclusions.setdefault(path, "could not be decoded")

    pool = source[~source["path"].isin(exclusions)].reset_index(drop=True)
    groups, group_of, used_links = build_groups(pool, links)

    label_of = dict(zip(pool["path"], pool["label"]))
    group_label = {}
    for group_id, paths in groups.items():
        labels = Counter(label_of[p] for p in paths)
        if len(labels) > 1:
            problems.append(f"{group_id} contains different labels {dict(labels)}: "
                            f"grouped under the most common one")
        group_label[group_id] = sorted(labels.items(), key=lambda kv: (-kv[1], kv[0]))[0][0]

    rng = random.Random(SEED)
    subset_of_group, wanted = assign_groups(groups, group_label, rng)

    assignments = pd.DataFrame({
        "path": pool["path"],
        "label": pool["label"],
        "group_id": pool["path"].map(group_of),
    })
    assignments["subset"] = assignments["group_id"].map(subset_of_group)
    assignments = assignments.sort_values("path").reset_index(drop=True)

    checks = run_checks(assignments, groups, used_links, len(pool))

    # --- write the files ---------------------------------------------------
    assignments.to_csv(ASSIGN_FILE, index=False, lineterminator="\n")
    ASSIGN_SIDECAR.write_text(f"{sha256_of_file(ASSIGN_FILE)}  split_assignments.csv\n", encoding="utf-8")

    link_text = defaultdict(list)
    for a, b, why in used_links:
        link_text[group_of[a]].append(why)
    rows = [{
        "group_id": gid, "size": len(paths), "label": group_label[gid],
        "subset": subset_of_group[gid], "reasons": " | ".join(sorted(set(link_text[gid]))),
        "paths": ";".join(paths),
    } for gid, paths in groups.items() if len(paths) > 1]
    pd.DataFrame(rows, columns=["group_id", "size", "label", "subset", "reasons", "paths"]).to_csv(
        GROUPS_FILE, index=False, lineterminator="\n")

    pd.DataFrame(sorted(exclusions.items()), columns=["path", "reason"]).to_csv(
        EXCLUSION_FILE, index=False, lineterminator="\n")

    manifest_hash = MANIFEST_SIDECAR.read_text().split()[0] if MANIFEST_SIDECAR.exists() else "sidecar not found"
    summary = build_summary(assignments, wanted, groups, group_label, used_links,
                            exclusions, checks, manifest_hash, problems)
    SUMMARY_FILE.write_text(summary, encoding="utf-8")
    print(summary)
    print(f"Files written to: {SPLITS_DIR}")
    if not all(ok for _, ok in checks):
        sys.exit("A check FAILED. Do not use this split. Send the summary above for help.")


if __name__ == "__main__":
    main()
